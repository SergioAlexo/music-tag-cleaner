## BPM and Key
- Table columns BPM and Key (on by default, v16 migration inserts them after Rating; a user who already placed them keeps their order).
- Value = file tag first, Rekordbox when the tag is empty. A small **RB** marker is shown when the shown value is Rekordbox's, or when Rekordbox disagrees with the tag (tooltip says what each side has). BPM compare: integer containers by rounded value, FLAC/OGG within 0.01. Key compare is notation-independent (`8A` == `Am` == `1m`).
- Both columns are editable curated fields and sortable (BPM numerically).
- Setting `keyNotation`: stored / camelot / openkey (Settings page). Display only; `src/lib/keys.ts` has the 24-key table, parsing of Camelot, Open Key and musical names (sharps, flats, unicode accidentals, "minor"/"major"), tests cover the full wheel in all directions.
- Rekordbox data now comes from a new `rekordbox_lookup(paths)` command (path-keyed, case-insensitive, works for any loaded file, not only ones under the Library root). Before, only index-joined rows had BPM/key and session files, which replace index rows in the merge, lost them.
- **Rekordbox → tags** button (Library toolbar, needs a selection and a configured rekordbox.xml): builds a preview (`rekordboxSync` preview mode, same table as Standardize), one row per field that is missing or different, per-row include checkboxes, applied through `applyUpdates`, one undo entry. BPM is written as an integer for MP3/M4A/AAC/WAV/AIFF (ID3v2 TBPM is defined as an integer, MP4 tmpo is an integer atom; Rust rounds there too) and with two decimals for FLAC/OGG/Opus. Key is written exactly as Rekordbox's `Tonality` (whatever notation Rekordbox exports in).

## Rating from Rekordbox
- `rekordbox_import.rs` now parses `Rating` (0/51/102/153/204/255 -> 0-5 stars, nearest step, clamped) and stores it in `rekordbox_track.rating` (column added by `ensure_rating_column` on old databases). `AverageBpm="0.00"` (unanalysed) is no longer stored as a BPM.
- Display: Stars column shows the **tag** rating when it is > 0, else Rekordbox's with an RB marker. Deliberate deviation from the brief's "Rekordbox XML -> POPM -> none": with XML first, a star click (which writes the tag) would visibly do nothing. "Rekordbox → tags" is how you make Rekordbox's rating win.
- Write path: the existing POPM writer (rewrites existing POPM frames in place, keeping each frame's email and play counter; adds one with an empty email if none exists; Vorbis `RATING` / MP4 `rate` elsewhere). No new POPM code.
- v16 migration forgets the saved rekordbox.xml mtime once, so the next launch re-imports and fills in ratings for exports imported before this version.
- Not verified: which POPM emails the owner's files really contain. The scan of `C:\Users\sopas\Music\Collection` was blocked by the session's permission classifier. The settings file also has **no rekordbox.xml path set**, so there was no XML to validate against; parsing is covered by a unit test on a synthetic export.
- Rekordbox usually keeps ratings only in its own database; a fresh XML export is required (File > Export Collection in xml format). For Rekordbox 6/7 users with no recent export, reading `master.db` is the C0 spike's job.
