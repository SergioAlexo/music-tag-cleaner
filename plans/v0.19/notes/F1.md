# F1 - Ship `mtc-mcp` as a Tauri sidecar

## What changed
- `scripts/build-sidecar.mjs`: builds `mcp/` (`cargo build --locked [--release]`, `--debug` flag for dev) for `TAURI_ENV_TARGET_TRIPLE` (else host from `rustc -vV`; passes `--target` only when the env var is set) and copies to `src-tauri/binaries/mtc-mcp-<triple>[.exe]`. Copy skipped when bytes already match; cargo is incremental so a re-run is ~1 s.
- `tauri.conf.json`: `bundle.externalBin: ["binaries/mtc-mcp"]`; `beforeBuildCommand` = `node scripts/build-sidecar.mjs && npm run build`; `beforeDevCommand` = `node scripts/build-sidecar.mjs --debug && npm run dev`.
- `src-tauri/build.rs`: writes an EMPTY placeholder `binaries/mtc-mcp-<TARGET>[.exe]` if missing, because tauri-build fails on a missing externalBin. This is what keeps bare `cargo test`/`cargo check` (fresh clone, the CI `ci.yml` job) working with no sidecar step. The placeholder cannot ship: `tauri build` runs the script first (beforeBuildCommand precedes the cargo build), and the script overwrites any file whose bytes differ.
- `.gitignore`: `src-tauri/binaries/`.
- `release.yml`: no new build step needed (script runs through beforeBuildCommand inside tauri-action; Rust is already installed before it). Added `mcp -> target` to the rust-cache workspaces and a comment. Matrix unchanged: windows-latest (x64), macos-latest (aarch64), ubuntu-22.04 (x64).
- `AiControlCard.tsx`: the path already came from `bridge_status.mcpExe` (`current_exe()` dir + `mtc-mcp[.exe]`), which is exactly where Tauri places sidecars (it strips the triple): Windows install dir beside the exe, Linux `/usr/bin` (deb/rpm) or `usr/bin` in the AppImage, macOS `Contents/MacOS/`. So the snippet uses the bundled path; the "not found" text now says reinstall or build it yourself, otherwise "ships with the app".
- `ci.yml`: unchanged; it never runs `tauri build`, and build.rs placeholder covers `cargo test`.

## Verification (Windows x64 host)
- `npm run build` ok; `npm test` 349 passed (1 skipped); `cargo test` in `mcp` 9 passed; in `src-tauri` 230 passed (fresh tree, placeholder created automatically).
- release.yml parsed with PyYAML (rust-cache `workspaces` is a two-line string).
- `npm run tauri build` (real, release): built mcp, copied 3.4 MB `mtc-mcp-x86_64-pc-windows-msvc.exe`, placed `mtc-mcp.exe` beside `music-tag-cleaner.exe` in target/release; both the MSI (`main.wxs` File entry) and NSIS (`installer.nsi`) installers reference it. Only failure was the updater-signature step ("no private key"), expected locally and unrelated (CI has the secrets).

## Watch on the next release run
1. Each of the 3 jobs should log `[sidecar] cargo build --locked --manifest-path mcp/Cargo.toml --release` then `[sidecar] copied -> .../mtc-mcp-<triple>`. A cold `mcp` compile (rmcp/tokio) adds a few minutes on first run (cache warms after).
2. `--locked` needs `mcp/Cargo.lock` committed and in sync (it is).
3. macOS: the sidecar is signed/notarized together with the app if Apple signing is configured (check log); an unsigned nested binary would fail notarization. Linux: confirm `/usr/bin/mtc-mcp` in the .deb (`dpkg -c`).
4. Windows: after install, `mtc-mcp.exe` sits next to `MusicTagCleaner.exe`; Settings -> AI control shows no "was not found" text.
5. If any job complains the externalBin is missing, `TAURI_ENV_TARGET_TRIPLE` vs host triple mismatch is the first suspect.
6. Updater: the sidecar is inside the NSIS/app bundle, so updates carry it; nothing extra in latest.json.
