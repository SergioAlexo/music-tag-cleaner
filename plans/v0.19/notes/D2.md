# D2 — Plugin SDK, AI buttons, themes, store view

Branch `worktree-agent-aab7f406640dce3e3` (from `d2-wip`, merged onto master incl. C1). Settings are **v23** (`themeId`, `pluginStoreUrl`, `plugins` records; the brief reserved 22, but master took 22 elsewhere, so the D2 step is `savedVersion < 23`).

## What
- **Plugin format + SDK** (`src/plugins/`): manifest validation (`manifest.ts`), permission table (`permissions.ts`), sandbox in an iframe + Worker with postMessage RPC (`iframeSandbox.ts`, `sandboxSource.ts`, `host.ts`), `PluginManager` (approval gate keyed by a hash of manifest+code, proposals held in memory until approved), `usePlugins` glue, and `plugins.*` registry actions (`pluginActions.ts`, so they are MCP tools via D1). Storage is `<appData>/plugins/<id>/` through `commands/plugins.rs` (path-safe ids/entries, 512 KB caps).
- **Examples** (`plugins-examples/`): Hide Genre button (declarative), Copy as Artist - Title, BPM range column, Neon theme. Tests load them from disk.
- **AI "New button"**: `NewButtonDialog` -> `buildNewButtonPrompt` -> `useAI.generateText` -> `parseGeneratedPlugin` -> `manager.propose(..., "ai")` -> the same `PluginReviewDialog` as MCP-created plugins. New backend commands `ai_generate_text` (Ollama) and `claude_generate_text` (Claude CLI, same offline check/tool denial). Manual backend: the dialog shows the prompt and takes the pasted answer.
- **Themes**: 5 bundled (Midnight, Rekordbox-ish, Serato-ish, High contrast, Warm vinyl) + installed `kind: "theme"` plugins. Applied as inline custom properties on `<html>` (`useAppTheme`), so removing a theme restores the stock look exactly. `forced ?? settings.theme` drives the dark class; `--radius-lg` and body font read `--app-radius` / `--app-font`. Settings -> Appearance and Plugins -> Themes share `ThemePicker`. **Follow OS stays the default** (`themeId: ""`).
- **Store**: `settings.pluginStoreUrl` (default empty -> "No store configured"). `commands/plugin_store.rs`: `plugin_store_index` (fetch, 1 MB cap) and `plugin_store_package` (download <= 2 MB, **SHA-256 verify**, unzip in memory with per-file decompressed caps, path-traversal rejection). The package is returned to the frontend and staged with source `"store"`; nothing is written until the person approves in the review dialog. `store.ts` parses the index (bad entries are skipped with a reason), resolves relative URLs, compares versions (update badge on the tab, Update button), uninstall is the existing row action. https only; http for loopback.
- `PLUGINS.md` (authoring guide, store publishing).

## Why / choices
- Unzipping into memory and writing only on approval (rather than into the plugins folder first) keeps one trust rule: nothing from the network or an AI touches the plugins folder before review. The approval hash would also have caught it, but this leaves no trace on reject.
- Store entries carry the manifest in the index (as the brief says) so the list can show permissions before download; the reviewed manifest is the one inside the zip, and the id must match the entry.
- Store fetch is automatic once per configured URL when the Plugins page opens (so the update badge works); it contacts only the owner-configured address.

## Click-through
1. Settings -> Appearance: tiles show; Follow OS selected by default. Pick Midnight -> app turns dark regardless of OS; Warm vinyl -> follows OS, rounder corners; back to Follow OS -> stock look.
2. Plugins -> Themes tab: same picker, same state.
3. Plugins -> Installed -> copy `plugins-examples/neon-theme` into the plugins folder -> Rescan -> Neon appears in the pickers.
4. Copy `hide-genre-button` in -> Rescan -> Review -> permissions + code shown -> Approve -> toolbar button hides the Genre column.
5. New button with AI (Claude CLI or Ollama backend): "a button that hides the Genre column" -> review dialog appears -> Reject leaves no folder; Approve works. With Manual backend: copy prompt, paste an answer.
6. Store tab with no URL: "No store configured". Serve a folder with `index.json` + zip on `http://localhost:8000/`, save that URL, Check: entries listed; Install -> review dialog -> Approve. Edit the index's `sha256` to be wrong -> "Checksum mismatch ... Not installed". Bump the version in the index -> Update badge on the tab and an Update button.
7. Uninstall a plugin (trash icon) -> folder and stored data removed.
8. From Claude Code over MCP: `plugins_docs`, then `plugins_create` -> the app jumps to Plugins with a review prompt.
