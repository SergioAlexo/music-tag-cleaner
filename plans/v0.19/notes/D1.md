# D1 - Action registry + AI-control bridge + MCP server

Settings version **21** (`aiControl`, default false; step guarded by `savedVersion < 21`).

## Parts
- **Registry** (`src/lib/actions.ts`, framework + JSON-Schema validator + `script.run` runner, no React/Tauri imports) and **registrations** (`src/lib/appActions.ts`). Every registration *wraps* an existing App.tsx handler; none was rewritten. App.tsx gained one import pair and one `useActionBridge({...})` block (just above the keyboard-shortcut effect) that hands the handlers over.
- **Bridge** (`src-tauri/src/bridge/mod.rs`): `tiny_http` on `127.0.0.1:<random port>`, `Authorization: Bearer <token>` on every route (token = 256 random bits per start, `bridge.json` {port, token, pid} in the app data dir, deleted on stop/close). Rejects requests with an `Origin` header and any `Host` that is not `127.0.0.1|localhost|[::1]:<port>` (DNS rebinding). The bind address is built from a constant (`bind_addr`), so no setting can open it to the network. Routes: `GET /health`, `GET /actions`, `POST /call {action, params}`. It is a relay: `bridge-request` event -> frontend registry -> `bridge_respond` command. Tauri commands: `bridge_set_enabled`, `bridge_status`, `bridge_respond`.
- **Frontend glue** (`src/hooks/useActionBridge.ts`): starts/stops the server with `settings.aiControl`, runs calls one at a time (they share selection/preview/busy state), waits ~90 ms after each action so React commits state the next one reads, logs every call to the Logs page (`AI: <action> ...`, params/result in details), shows the in-app confirm for `dangerous` actions unless "run risky actions without asking (this session)" is ticked (never persisted).
- **Settings card** (`src/components/AiControlCard.tsx`, Settings after the Library index card): switch, status, session-only "allow without asking", copy buttons for the CLI command and the Claude Desktop JSON.
- **MCP server** (`mcp/`, separate crate/lockfile, not part of src-tauri's build): official `rmcp` 3.5 with stdio. `tools/list` re-fetches `GET /actions` every time, so new registrations (C1, D2 plugins) appear without a rebuild or restart. Tool name = action id with `.` -> `_` (`session.list` -> `session_list`). Annotations: `readOnlyHint`, `destructiveHint`. Extra tool `mtc_connection_status`. Resources `mtc://session`, `mtc://selection`. Reads `bridge.json` on every request (override with `MTC_BRIDGE_FILE`).

## Install
Build once: `cd mcp && cargo build --release` -> `mcp/target/release/mtc-mcp.exe`. Settings -> AI control shows the path it expects (next to the app exe) with copy buttons; the command is

```
claude mcp add music-tag-cleaner -- "C:\path\to\mtc-mcp.exe"
```

Claude Desktop `claude_desktop_config.json`:

```json
{ "mcpServers": { "music-tag-cleaner": { "command": "C:\\path\\to\\mtc-mcp.exe", "args": [] } } }
```

Turn on Settings -> AI control -> Allow AI control first (the app must be running).

## Tool list (51 actions; each is also an MCP tool)
Queries (read-only): `app.info` `session.list` `session.selection` `library.search` `library.stats` `track.get` `playlists.list` `settings.get` `columns.list` `changes.get`

Tag edits (undoable): `tags.edit` `tags.editRaw` `tags.setRating` `tags.generateIds`
Preview-then-apply (build the preview; read with `changes.get`; write with `changes.apply` or drop with `changes.cancel`): `tags.standardize` (characters | capitalization | removeChars) `tags.clearFields` `tags.aiClean` `tags.rekordboxToTags` `tags.migrateTrackIds` `language.detect`, then `changes.apply` `changes.cancel`
History: `history.undo` `history.redo`
Files (risky, in-app confirm): `files.rename` `files.renameToStandard` `files.delete` `files.standardizeContainers` `duplicates.delete` `convert.run` `backup.restore`
Artwork: `artwork.standardize` `artwork.remove` `artwork.find` (opens dialog) `artwork.junkArt` (opens dialog)
Dialogs for a human to finish: `organize.open` (Move to collection) `convert.open` `stems.open` `tags.unifyIds`
Other: `lyrics.fetch` `backup.tags` `backup.archive` `script.run` (steps + `dryRun`)

Risky = `dangerous: true` in the registration (shown in the MCP description and as `destructiveHint`). `files.delete`, `files.standardizeContainers` and `duplicates.delete` already show the app's own confirm, so they are flagged `confirmsItself` and are not asked twice.

Adding an action (C1 playlists, D2 plugins) is one `reg.register({id, title, params, run})` call; add an `AppEnv.h` member only if it needs an App.tsx handler.

## Choices and deviations
- **No WebSocket.** The brief said HTTP + WebSocket; nothing needs server push (MCP polls the registry), so HTTP only.
- **Sidecar bundling not done.** `externalBin` makes `tauri build` and `tauri dev` fail when the triple-named binary is missing, so wiring it needs a release-workflow step (build `mcp`, copy as `mtc-mcp-<triple>`). Settings shows the path next to the app exe plus a hint to build it; that is the follow-up.
- Move-to-collection is exposed as `organize.open` (the dialog with the preview; the person presses Apply) rather than a direct `organize.move`, so an AI cannot mass-move files without a human looking at the plan. A direct dangerous variant is a 10-line registration if wanted.
- Selection-based handlers read `filesApi.selectedPaths`, so actions taking `paths` select exactly those (changing the table selection) and require them to be in the session (`library.addToSession` / `session.open` first).
- `duplicates.scan` is not registered: the scan lives inside DuplicatesPage state. `duplicates.delete` takes paths directly.
- `settings.get` hides keys that look secret (api key/token/secret/password); none exist today.

## Tests
- TS: `actions.test.ts` (schema validation, dangerous gate, unregister, script dry-run/stop/continue/settle, clamp), `appActions.test.ts` (registered set, setColumns hide, select, wrapped-handler call order, dry-run plan flags dangerous, denied dangerous action, secret hiding), `useSettings.test.ts` (v21).
- Rust `src-tauri` (`cargo test bridge`): missing/wrong/empty token rejected on every route, right token accepted, action error vs transport error codes, Origin and foreign Host refused, bind address always `127.0.0.1`, token length/uniqueness/constant-time compare, and a **real socket** test (401 without/with wrong token, 200 with it).
- `mcp` (`cargo test`): bridge.json parsing, bearer header sent, `/call` body, ok:false -> action error, 401 -> not-connected, tool name sanitising, schema/hints, collisions, bad schema fallback.
- End-to-end through stdio against a fake bridge (`initialize`, `tools/list`, `tools/call`, `resources/read` all answered correctly).
- Results: `npm test` 245/245, `npm run build` ok, `src-tauri cargo test` 204 passed, `mcp cargo test` 9 passed.

## Click-through
1. `npm run tauri dev`; Settings -> AI control: tick Allow. Status shows `Listening on 127.0.0.1:<port>`; `bridge.json` exists in the app data dir. Untick: status stops and the file disappears.
2. `cd mcp && cargo build --release`, copy `mtc-mcp.exe` beside the dev exe (`src-tauri/target/debug/`), run the shown `claude mcp add ...`, start `claude`, `/mcp` lists music-tag-cleaner with ~52 tools.
3. Ask Claude: "list my session", "hide the Genre column", "select the first 3 tracks and show standardize capitalization (title) as a preview", then "apply it" (preview appears in the app, apply writes, Undo works).
4. Ask it to delete a file: the app shows the Allow dialog (or the Recycle Bin confirm); decline -> Claude sees a refusal. Tick "run risky actions without asking" -> `files.rename` runs without the dialog (use a copy).
5. Logs page shows each `AI: ...` call with params/result.
