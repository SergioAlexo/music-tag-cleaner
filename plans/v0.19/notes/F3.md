# F3 - Click-to-seek lyrics + Lyrics output window (DJ + karaoke visuals)

Settings version **26** (`savedVersion < 26` step; 25 is F2's).

## What changed

### Click-to-seek (`src/lib/nowPlaying.ts`, `AudioPreview.tsx`, `LyricsPanel.tsx`)
- New seek channel next to the position publishing: `requestSeek(path, ms)` / `onSeekRequest(handler)` (first handler that returns true wins). `AudioPreview` registers one per instance; it answers only when its path matches **and it is the instance that published last** (`setNowPlayingOwner` / `isNowPlayingOwner`), because the same file can be mounted in several lists.
- The handler does what the scrub bar does (`ensureLoaded`, set `currentTime`, and if paused `takeOverPlayback(pause)` + play), so the single-global-player contract is unchanged. Pure part: `seekTargetSecs(ms, durationSecs)` (clamps into the track, NaN/negative -> 0).
- Clicking a synced line in the panel seeks the player; with no player for that file a toast says to press play first.

### Lyrics output window
- **Window**: created and steered from **Rust** (`src-tauri/src/commands/lyrics_output.rs`, label `lyrics-out`, URL `index.html?view=lyrics-out`; `main.tsx` renders `LyricsOutputPage` for that query). Commands: `lyrics_output_open/close/is_open/monitors/place/fullscreen/is_fullscreen`. Doing it in Rust means no JS window permissions at all.
- **Capabilities**: new `src-tauri/capabilities/lyrics-output.json`, `windows: ["lyrics-out"]`, permissions `["core:event:default"]` only (listen + emit). `default.json` (main) is untouched; `tauri.conf.json` untouched (the window is created on demand, not declared).
- **Data flow**: `LyricsOutputBridge` (main window, renders nothing) emits `lyrics-out:config` (style settings), `lyrics-out:track` (lines + title, when the track changes), `lyrics-out:time` (`{path, timeMs, playing}` on every player update, prelisten mode). The window emits `lyrics-out:ready` on mount (the bridge then re-sends everything, so a reload/late open works) and `lyrics-out:monitor` (the bridge saves it to settings). The window has no logic of its own: between time updates it extrapolates with its own `performance.now()` clock (`extrapolate`), so a busy main window does not stall it. While the window is open the main window polls `lyrics_output_is_open` every 2 s to notice it being closed with its X (observing the close event would need window permissions).
- **Display** (`pages/LyricsOutputPage.tsx`, pure parts in `lib/lyricsOutput.ts`): current line big and centred, next line smaller, previous line optional; the changed line fades/rises in (keyframes in `styles.css`, off under reduced-motion). Sizes scale with window height. Styles: **Clean** (white on black), **Karaoke** (current line fills left to right across the line's time span, capped at 8 s), **Neon**, **Lower third** (bar bottom-left, current + next, for OBS). Background: black / transparent / chroma green (#00b140), applies to every style. Font size slider 24-160, sync offset +/-100 ms steps (positive = lyrics earlier), previous line toggle. All in `settings.lyricsOutput`, edited from the Lyrics panel -> "Output" drawer, or by the `lyrics.output.style` action.
- **Fullscreen / monitors**: F or double-click toggles, Esc leaves. A hover control bar (fades after 2.5 s, cursor hides) has "Move to monitor..." (lists monitors via the window API; moves the window onto it and goes fullscreen) - the chosen monitor index is saved and the window is moved there (not fullscreen) the next time it opens.
- **Manual mode** (Source = "Manual" in the panel): the source track is the first selected library track (music plays from Rekordbox etc.). The output window owns a manual clock: Right/Down/N/Enter = next line, Left/Up/P = previous (re-bases the clock so that line is exactly the current one, accounting for the offset), Space = pause/resume, "Start at" button + mm:ss box starts the clock at a time, `[` / `]` nudge the sync by 100 ms (window-local; the saved offset is set in the panel). Plain-only lyrics (no timestamps) can be stepped line by line but never auto-run. A new track resets the clock to 0:00 paused.
- **Actions** (`appActions.ts`, all safe): `lyrics.output.open`, `lyrics.output.close`, `lyrics.output.style` (style, background, fontSize, offsetMs, showPrev, mode; validated/clamped by `normalizeOutputSettings`, persisted).

## Future: Mixxx-follow mode (not built)
The bridge already sends `{path, timeMs, playing}`; a Mixxx source only has to produce the same triple.
1. **Controller script (best)**: a tiny JS controller mapping loaded in Mixxx 2.5 reads `engine.getValue("[ChannelN]","playposition")`, `"duration"`, `"play"`, and the track via `engine.getString`/`track_loaded` + the track-location (2.5 exposes metadata through `[ChannelN] ... ` controls and `engine.getValue` string getters on newer builds; otherwise match by artist/title). On a 20 Hz timer it posts a JSON line over a local UDP/WebSocket socket (Mixxx scripts can do `engine.makeConnection` + a socket via `script.` helpers only in the OSC/HTTP-capable builds; the portable variant is writing a small JSON file that this app watches with the `notify` crate).
2. **OSC**: Mixxx 2.5 has no built-in OSC, so (1) is the route; a script emitting OSC to a local port that Rust (`rosc`) listens on is equivalent.
3. **Now-playing text** (Mixxx "Live broadcasting"/OBS now-playing file) gives artist/title only, no position: enough to switch track and start the manual clock at 0.
4. Rust side: a `mixxx_follow` command listening on the local port, mapping the active (audible, highest-volume) deck to a library path (the library index already resolves by artist/title or location), then `emit`ting the same `lyrics-out:time`/`track` events straight to `lyrics-out` (no main-window round trip). Drift: re-sync on every position message; keep the +/-100 ms nudge.

## Click-through (`npm run tauri dev`)
1. Prelisten a track that has a `.lrc`; open the Lyrics panel; click a line: playback jumps there. Pause, click another line: it jumps and resumes. Start a second track, click a line of the first panel state: only the playing track moves.
2. Lyrics panel -> "Output" drawer -> "Lyrics output": a window opens (no capability error in the terminal). It shows the current and next line following the player; pause freezes it.
3. Change Style (Clean/Karaoke/Neon/Lower third), Background (Transparent shows the desktop through; Chroma green), Size slider, "Show the previous line", Sync +/-100: the open window updates live; restart the app, settings persist.
4. In the output window: press F (fullscreen), Esc (back), double-click (fullscreen). Move the mouse: control bar appears; "Move to monitor..." -> pick the second screen: window goes there fullscreen. Close and re-open: it comes back on that monitor (windowed).
5. Keep the main window busy (e.g. start a big library scan): the output keeps animating.
6. Source = Manual: select a track with lyrics in the library, open the output; use Right/Left or Next/Prev to step; "Start at" 0:30 runs the clock; Space pauses; `[` / `]` shifts sync. Plain-only lyrics: steps by line, Start disabled.
7. Actions (AI bridge / palette): `lyrics.output.open`, `lyrics.output.style {"style":"neon","fontSize":90}`, `lyrics.output.close`.
8. Close the window with its X: the panel button returns to "Lyrics output" within ~2 s.

## Not verified on real hardware
Moving + fullscreen onto a second monitor and the transparent-background compositing in OBS need the owner's rig; `set_fullscreen` after `set_position` is the standard Windows borderless-fullscreen path. macOS would need the `macos-private-api` feature for a truly transparent webview (Windows is the owner's platform).
