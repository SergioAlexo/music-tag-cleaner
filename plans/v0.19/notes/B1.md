# B1 — Library sidebar: Albums, "No genre", search & add, Refresh

Branch `worktree-agent-ae5d1bd1b96a866f4`. Settings version 17.

## What changed
- **Facets** (`src/lib/facets.ts`): Genres and Albums are one code path. `Facet = "genre" | "album"`; add one by adding an entry to `FACETS`, a column and an arm in `Facet` (library_index.rs). `language` (B3) is deliberately not in the type yet, since it has no indexed column. Sidebar, load hook, rename flow and session source (`{ kind: "facet", facet, name, artist }`, replaced `kind: "genre"`) are generic.
- **Rust** (`library_index.rs`): `library_facets(facet)` and `library_paths_with_facet(facet, name, artist)`. Albums group by (album, trimmed album artist), so two "Greatest Hits" stay apart. The empty bucket (`name == ""`, NULL or blank field) is returned first and shown as "No genre" / "No album". `library_genres` / `library_paths_with_genre` still exist (other callers) but the hook now derives `genres` from the genre facet. db-path resolution untouched.
- **Albums tab** (Genres/Albums are virtualized lists, `VirtualList`): count/A-Z toggle per facet (localStorage `librarySidebar.<facet>Sort`), search box, click loads (new tab / replace / filter dialog, same rules as genres), pencil on hover renames inline and retags every indexed track through `retag_field` (field `album`; the confirm dialog names the album artist). Loaded-but-unindexed tracks go through `editField` so undo covers them.
- **Search tab**: `searchTracks` over the whole index, deferred while typing, 2000-hit cap, windowed rows, per-row Add, tick boxes + "Select all" + "Add N". Adding merges into the current session (`useFiles.addIndexed`), seeds tags from the index and re-reads real tags in the background (same `hydrate` as a facet load). Already-present tracks show "In session". The session becomes "manual" (a later genre click asks). No drag anywhere.
- **Refresh** (sidebar footer): runs the existing incremental `index_library` (mtime+size), shows `Reading N of M…` while it runs and then "N new, M changed, K removed" (plus "(n unreadable)"). A ref guards against overlapping scans (startup, Settings, button, focus).
- **`libraryAutoRefresh`** (settings v17, default off, toggle in Settings -> Library): re-scans when the window regains focus (max once a minute), toasts only if something changed.
- **A3 follow-ups**: index v4 stores the file's own BPM/key tags (`bpm_tag`, `key_tag`, added to existing databases with `ALTER TABLE` in `migrate_columns`; `INDEX_VERSION` 3 -> 4 forces one full re-read). `IndexedTrack.tagBpm/tagKey` -> `indexedToTags` fills `TagData.bpm/key`, so index-only rows show tag BPM/key first, Rekordbox as fallback (A3's rule). `trackSearch` now searches BPM (stored text and rounded: `bpm:128` finds 127.99; a bare number too) and Key (every spelling: `key:8A`, `key:Am`, `key:1m` are the same key; `key:` is exact, not substring). Because all spellings are searchable, search does not depend on the active `keyNotation`. Only file tags are searched; Rekordbox-only BPM/key (index `bpm`/`key`) is not, since it is not in `TagData`.

## Deviations
- No `notify`-crate file watcher: focus-triggered refresh instead (no new native dependency; same cost profile since the scan is incremental). Gated by the same setting name the brief gave.
- `language` is not in the TS/Rust facet types yet (no column to query); extending is the three-place change above.
- First launch after this build re-reads every file once (index version bump). It runs in the background like any startup index.
- Plain-word search for a short key like `am` also matches any text containing it (it is in the haystack); use `key:` for exact key matching.

## Click-through (`npm run tauri dev`, with the real Library folder configured)
1. Start the app. First launch re-reads the library (progress shows in Settings' index card); afterwards open the Library page.
2. Sidebar -> **Genres**: top row is "No genre" (italic) with a count; click it: those tracks load as the batch. Click a real genre: loads. Toggle A-Z / count.
3. Sidebar -> **Albums**: list shows albums, same-titled albums by different album artists as separate rows ("Greatest Hits - Queen" vs "- ABBA"). "No album" is first. Click one: loads; tab is named after it. With a hand-built batch the session dialog appears (new tab / replace / filter).
4. Hover an album row, click the pencil, type a new name, Enter: confirm dialog names album + album artist + count; accept and check the tag in the table (use a copy of a few files, not the real library).
5. Sidebar -> **Search**: type `gravity`, `bpm:128`, `key:8A`, a bare `128`. Results scroll smoothly with a broad query (e.g. `a`). Click **Add** on one row: it appears in the current session (and "In session" shows). Tick several, **Add N**. Confirm the session keeps its previous files and undo history.
6. Change `keyNotation` in Settings to Camelot and search `key:Am` still finds the same tracks.
7. A BPM/Key cell for a track that is only in the library (load a genre, not a folder) shows the **file's** tag value, falling back to Rekordbox with the RB marker.
8. Drop a new mp3 into the Library folder, press **Refresh** (sidebar footer): progress, then "1 new, 0 changed, 0 removed"; the genre/album counts update. Delete it, Refresh: "0 new, 0 changed, 1 removed".
9. Settings -> Library -> turn on "Refresh the library when the window gets focus"; add a file, switch to another app and back: a log entry "Library refreshed: ..." appears (Logs page; no toast).
