## 1. Waveforms

Swept the decoder (`compute_waveform_symphonia`, new opt-in `real_library_waveform_sweep`
test) over the owner's folders:

| Folder | Files | Result |
|---|---|---|
| `Music\Collection` (the library root; all MP3) | 4289 | 4289 decode, 0 errors, 0 truncated decodes (<90% of header length), 0 all-zero |
| Recordings / Acapellas / Archive / rekordbox / PioneerDJ | 107 / 17 / 18 / 26 / 7 | all decode; 51 Recordings WAVs are digital silence (-91 dB per ffmpeg), not a bug |
| Samples (first 1500 of ~6900 wav/aif) | 1500 | all decode; 8 are 2-frame silent f32 hits |

So **symphonia is not what drops waveforms on this library**: there is no format that
fails to decode. (167 rows in the library index point at files that no longer exist;
those get "Couldn't read the file".) The root causes are in how the result was
produced/consumed:

1. **A cache-write failure threw away a finished waveform.** `get_or_compute_waveform`
   did `execute(UPSERT)?` after decoding. While a duplicate scan holds the sqlite write
   lock (busy timeout 10 s) the UPSERT failed with "database is locked" and the whole
   command returned Err, so the track showed no waveform until the scan was over. Cache
   writes (and a failing cache *read/open*) are now best-effort.
2. **Unbounded parallel full-file decodes.** A duplicate group mounts one `Waveform` per
   row and each fires `get_waveform` at once; every call is a full decode plus its own DB
   connection. They starved each other (and the scan) and queued behind the busy timeout.
   Now at most 4 decode at a time (`WAVEFORM_MAX_PARALLEL`).
3. **Silent failure.** `Waveform.tsx` swallows the error into `[]` (A1's file). The command
   now returns readable `Err` strings ("Couldn't generate a waveform: ..."), never an empty
   `Ok`, so A1 can show `String(e)` instead of a blank box.

Required hardening, all done and tested:
- empty / NULL / unparsable cached peaks = cache miss (test `an_empty_cached_waveform_is_recomputed`);
- a decode that dies mid-stream keeps the peaks decoded so far (`a_truncated_file_keeps_the_peaks_decoded_so_far`);
  a decode that covers < 90 % of the header duration is retried with FFmpeg when installed and the longer result wins;
- FFmpeg fallback `ffmpeg -i f -vn -ac 1 -ar 8000 -f s16le -` streamed (never held whole) when symphonia
  fails or decodes nothing (`ffmpeg_peaks_agree_with_symphonia...` runs only if ffmpeg is on PATH);
  `get_waveform` finds ffmpeg via `ffmpeg::find_ffmpeg`;
- peak output is unchanged, so no `algo_version` bump (a bump would also invalidate every cached fingerprint and the
  fingerprint-hash keys Rekordbox cue imports rely on).

Not done (A1 / out of scope): UI retry/error display in `Waveform.tsx`; decode time for very long WAVs (an
hour-long recording takes tens of seconds).

## 2. Duplicate recall

Real library, `Music\Collection`, 4289 files, same warm fingerprint cache for both runs:

| | groups | duplicate | alternate | scan time |
|---|---|---|---|---|
| before (HEAD) | **0** | 0 | 0 | 274 s |
| after | **226** | 0 | 226 (208 `tags`, 18 `tags+audio`) | ~140 s |

The library is the *leftover* after the owner already deleted everything the old scan found, so
0 before is consistent with "quite a few weren't found": 693 files share a normalised artist+title
in 312 keys. Examples of newly found groups (anonymised; all `alternate`, never suggested for removal):
- Artist A - Song 1 (two copies, 3:50 vs 3:37, different edits; no fingerprint overlap in the first 2 min)
- Artist B - Song 2 (x4 copies incl. a `Don t` vs `Dont` spelling variant, 4 files)
- Artist C - Song 3 / Artist C - Song 3 (Some Remix) (original + remix, file name carries the remix tag)
- Artist D - Song 4 (x3, one named `P.i.m.p.` vs `P I M P` vs `Pimp`)
- Artist E - Song 5 with 3:15 vs 3:51 versions (radio vs extended style length gap)

Root causes found (verified by test before fixing):
1. **Tags were never used.** Only first-2-minute fingerprints. Radio vs extended with a different
   opening, or any pair with no overlap in that window, never matched. New stage 4: bucket by normalised
   title, `same_song()` (artist overlap / prefix) -> always `alternate`, `reason` "tags+audio" if a >=10 s
   segment scores <= 8 else "tags". Pairs with real lengths < 0.2 ratio are not tag-matched.
   Normalisation: accents, case, apostrophes/punctuation, `&`/and, leading "The", `feat./ft.` (title and artist),
   `(..)`/`[..]`/` - ` version tags (radio, extended, clean, dirty, intro, DJcity Intro, instrumental, acapella,
   original mix, ...Remix) with "original mix" = no tag; real title brackets like `(Everybody Dance Now)` or
   `Live Is Life` are kept. Missing tags fall back to the file name (`Artist - Title`, leading `01 -`/`8A - 126 -`
   and trailing ` - 000224` ids stripped). Version tags in the file name count even when the tag title is clean.
2. **Byte-identical copies were excluded from the fingerprint stage entirely**, so A, A-copy and A-extended never
   linked. Exact groups are now unioned and one representative takes part in comparisons.
3. **Analysis window is capped in samples, not seconds** (44.1 kHz stereo = 120 s, 48 kHz = 110.3 s), so a
   re-encoded 48 kHz copy of the same recording failed the 5 % length gate and showed as `alternate`.
   Real header lengths (lofty) now decide `duplicate`-vs-not when known.
4. **Capped durations made 3:00 radio and 8:00 extended both "120 s"**, so a matching opening was a
   `duplicate`. If real lengths differ > 5 % (+1 s) a would-be duplicate is now an `alternate`.
   Same audio with different version tags (clean vs dirty) is also an `alternate`.

Regression fixture (step 0), in `duplicates.rs` tests: thresholds pinned (`ALTERNATE_SCORE_MAX` 4.0 etc.),
radio-inside-extended stays alternate, identical audio/different melodies unchanged, shared-jingle cases are
only reachable via the unchanged strict thresholds (tag matching uses the loose check only to *label*), exact
copies keep `exact-` ids and score 0, and the fragmented-genuine-duplicate case (Hotel Room Service) is left
alone: `classify_pair` still uses the single largest segment.

## Left alone, and why
- Strict audio thresholds and single-largest-segment coverage (two earlier "fixes" each broke a real case).
- `DuplicateGroup` gained `reason` (string); `types.ts` is A3's, so TS reads it via `groupReasonLabel(reason?)`
  in `src/lib/duplicates.ts`. A1 can show it. Old builds/UI ignore the extra field.
- Remixes are grouped as alternates of the original (e.g. "Song" and "Song (X Remix)") by design; the owner's
  tags drop the remix name so this is the only way they link. They default to Skip like every alternate.
- ROADMAP.md entry not appended (three agents edit in parallel; add one at merge time).
- Tag-only groups can include two genuinely different recordings with the same title by overlapping artists;
  shown as "tags" so the UI can say the audio wasn't confirmed.
