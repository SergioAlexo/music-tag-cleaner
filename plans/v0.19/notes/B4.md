# B4 notes: auto-move to collection + backup-able library file

## What shipped
- `src-tauri/src/commands/organize.rs` (new): pattern rendering, move plan/preview, safe move, undo, CSV path map, db relocation, snapshot export/restore, snapshot-on-exit hook.
- `library_index.rs`: only `db_path()` changed (calls `organize::resolve_db_path`). Merge with B1 = one-line conflict at most.
- UI: `OrganizeDialog.tsx` (preview table, warning, result, Undo), `OrganizeSettingsCard.tsx` (Settings), context-menu entry "Move to collection..." (TrackTable -> LibraryPage -> App).
- Settings: `collectionRoot`, `organizePattern`, `autoMoveOnSave`, `snapshotFolder`, `snapshotOnExit`, `snapshotKeep`. `CURRENT_SETTINGS_VERSION = 20` (code was at 15 on this branch). The migration step is a no-op comment (defaults come from the merge); renumber freely.
- `chrono` added as a direct dep (already in Cargo.lock transitively) for local-time file names.

## Behaviour
- Tokens: genre album albumartist artist title year bpm key trackid ext. Missing genre/album/artist -> "Unknown ...", missing title -> file stem, missing year/bpm/key/trackid -> empty (empty folder segments are dropped). bpm/key come from the raw tag dump, not the Rekordbox table.
- Illegal Windows chars -> `_`; `/` inside a tag value -> `-` (never adds a folder). Reserved names (CON...) prefixed `_`, trailing dots/spaces trimmed. Total path capped at 250 chars by shortening the file stem only; extension always kept.
- Conflicts: " (2)" only when the target is a different file (canonicalize check, as in `rename_file_blocking`); also de-dupes inside one batch.
- Move: `fs::rename`; if that fails (cross-volume) copy to `.part`, verify byte size, publish, delete source. Never overwrites.
- After a move: index rows re-read via `reindex_paths`, session rows remapped (`filesApi.remap`), tag cache rekeyed. Old->new CSV written to `<app data>/move-maps/move-map-YYYYMMDD-HHMMSS.csv` (for C2 sync); the dialog has "Show path map".
- autoMoveOnSave: runs after "Apply" in the preview (applyPending) for files outside `collectionRoot`.

## Library file
- Location is stored in `<app data>/db-location.txt` (the db can't hold its own location). Empty = default. If the chosen folder is missing (unplugged drive) the app falls back to the default and Settings shows a warning.
- Change: `VACUUM INTO` the new path (folds in the WAL), `integrity_check` + track-count compare, switch pointer, old file -> `.bak`. Refuses to overwrite an existing file.
- Snapshot: `library-YYYYMMDD-HHMM.sqlite` (VACUUM INTO) + `library.json` (all `library_track` columns generically, roots, any table with "playlist" in the name). Prunes to the newest N. Snapshot-on-exit runs from the main window's CloseRequested; config is mirrored to `snapshot-config.json` because Rust can't ask JS at exit.
- Restore: verifies the snapshot, keeps current as `<db>.pre-restore.bak`, swaps in.
- Do NOT put the live db in OneDrive/Dropbox: sqlite and sync clients corrupt each other. Snapshots are what to sync.

## Deviations / limits
- Undo is a dedicated "Undo move" in the result dialog, not the tag history stack (history is keyed by path and has no path-change entry). Only available until the dialog is closed.
- Sessions in other tabs are not remapped; only the active session's rows/selection (the library index is updated for all).
- No toolbar button, only the context menu + Settings.
- Sidecar `.bak` tag backups (has_backup) are not moved with the file.
- autoMoveOnSave hooks Apply only (not inline cell edits).
- Cross-volume move is tested via `copy_verify_delete` directly (no second volume available).
