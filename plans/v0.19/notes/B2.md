# B2 — Artwork lookup + junk-art detection

## What shipped
- `src-tauri/src/commands/artwork.rs`: MusicBrainz recording search (duration within 5 s) then Cover Art
  Archive `front-1200` (falls back to 500 / original), then iTunes (`100x100bb` -> `1200x1200bb`), then
  Deezer `cover_xl`. Global MusicBrainz rate limiter (1.1 s spacing), real User-Agent, sqlite response cache
  (30 days, 404s cached too) in the module's own `artwork.sqlite`.
- `files.rs`: one additive `pub(crate) apply_cover_bytes` reusing `recompress_cover` / `embed_picture_bytes`
  (honours `artworkMaxDim` / `artworkJpegQuality`, returns before/after for undo history).
- Junk detection: 64-bit dHash per embedded cover (`art_hash` table, incremental on mtime+size), greedy
  clustering at Hamming <= 6, cluster = >=3 tracks across >=3 distinct artists. Suspicion score
  (tiny/small, near-solid, <=3 main colours; flagged at >= 0.7). Blocklist is a table in `artwork.sqlite`
  (`junk_blocklist`), matched at Hamming <= 6.
- UI: `ArtworkDialog.tsx` (`ArtworkDialog` single pick / bulk auto-pick with 75/85/95% threshold;
  `JunkArtDialog` scan, clusters, Mark as junk, Remove art, Find real artwork, flagged list),
  `artworkMatch.ts` ranking. Entry points: track context menu "Find artwork…", Library toolbar
  "Find Art" and "Junk Art". Both writes go through undo history (`__coverArt`).
- Candidate ranking lives in TS (`artworkMatch.ts`): confidence = title/artist similarity (+/- duration,
  MB score); rank adds same-release bonus, single-vs-album preference, compilation penalty.

## Settings
No settings change: the blocklist is in sqlite, so **no settings migration** was needed (the reserved
version bump is unused). The merger can skip it.

## Tests
Rust: hash stability across JPEG q95/75/50 + rescale, distinct images far apart, clustering, ordering,
suspicion, rate limiter, cache, escaping; `#[ignore]` `mb_live_finds_cover_for_known_track` (passes live);
`#[ignore]` `owner_library_clusters` (set `MTC_INDEX_DB` to a copy of the index). TS: `artworkMatch.test.ts`.

2. `cccccccccccccccc` 46 / 39, 800px (Desiigner - Panda)
3. `0707070707070707` 43 / 41, 800px
4. `0733333333333307` 32 / 29, 1280px (Alleh - La Radio)
5. `3333232333331717` 14 / 11, 600px
6. `1f1f0f0f17071707` 11 / 11, 600px
Visually the top hashes are very regular (0f0f..., cccc...), i.e. flat/banded images - likely pool logos or
blank placeholders; confirm by eye in the dialog (thumbnails shown). Album tags are empty on all these, so
"same album" is not a signal here. 9 tracks flagged "near-solid colour"; 0 tiny. Clusters below ~15 tracks may
include hash collisions of low-detail covers; the user marks them manually, nothing is auto-removed.

## Deviations / notes
- Nominal sizes are shown for CAA/iTunes/Deezer (real pixel size is only known after download).
- Scan reads the library via `library_track` (has_cover=1) read-only; depends on that table/columns staying.
- Merged master twice (4b0ac6a, then f753b87); conflicts were only additive (main.rs, App, TrackTable, LibraryPage).
- Live tests need a rustls provider installed (the app gets one from the updater plugin); the test installs ring.

## Manual click-through
1. Right-click a track > Find artwork…: current art + up to 6 candidates; pick one; Ctrl+Z restores old art.
2. Select several > Find Art > Auto-pick best at 85%: statuses per row; one undo entry.
3. Library > Junk Art > Scan: progress, clusters with thumbnails; Mark as junk, Rescan (stays marked);
   Remove art / Find real artwork on a cluster; "Not junk" unmarks.
