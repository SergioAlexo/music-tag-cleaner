# B3 - Lyrics (LRCLIB) + Language field

Settings version **20** (v19 is B2's; the migration step is guarded by `savedVersion < 20`, so the chain is valid whichever lands first). Index version 5.

## What changed

### Lyrics (`src-tauri/src/commands/lyrics.rs`, `src/lib/lrc.ts`, `src/lib/lyrics.ts`, `src/lib/nowPlaying.ts`, `src/components/LyricsPanel.tsx`)
- **Source**: LRCLIB `/api/get` (artist, title, album, rounded duration), then `/api/search` with the exact artist+title, then `/api/search` with the decorations stripped (`(Original Mix)`, `feat. X`, `- Radio Edit`, second artist). A search result must be within 4 s of the file's duration, synced beats plain, closest duration wins. User-Agent is `music-tag-cleaner/<version> (repo url)`.
- **Busy service**: LRCLIB answered 503 for ~25% of lookups in a live run, so 429/502/503/504 are retried (1.2 s, 2.4 s, 3.6 s) before an error is reported. Network errors are never cached.
- **Cache**: table `lyrics_cache` in the library database (created lazily, key = normalised `artist\u0001title`, so album/duration differences between copies don't re-hit). Hits are kept forever, misses (including "instrumental") for 14 days, then retried. The same cache feeds the lyrics panel and language detection with no network.
- **Storage** (setting `lyricsStorage`, default `sidecar`; Settings -> Library -> "Store fetched lyrics"):
  - sidecar `.lrc` next to the audio (synced lyrics); plain-only lyrics go to `.txt`, never a timestamp-less `.lrc` (karaoke tools would show it all at 0:00). Existing sidecars are not overwritten.
  - embedded: plain text via the existing `write_raw_field_blocking(path, "Lyrics", ..)` (ID3 USLT, Vorbis `LYRICS`, MP4 lyrics atom), which edits the file's own parsed tag, so GEOB/PRIV/POPM are untouched. Synced SYLT is **not** written: lofty's generic `Tag` cannot express it, and a hand-built ID3 frame would mean rebuilding the tag.
  - `both`.
- **Commands**: `lyrics_fetch(paths, storage, overwrite)` (one result per path: `synced | plain | instrumental | notFound | have | error`; 4 requests in flight), `lyrics_for_path(path)` (sidecar -> embedded -> cache, offline), `detect_languages(paths)`.
- **UI**: right-click -> "Fetch lyrics" (single or selection; progress in the status bar, summary toast like "12 synced, 3 plain, 5 not found"). `LyricsPanel` is a single floating panel (bottom right, toggle button, remembered) fed by `useNowPlaying`: `AudioPreview` publishes `{path, timeMs, playing}` to a tiny store (`lib/nowPlaying.ts`), the panel highlights/scrolls the current line (binary search, `lib/lrc.ts`), shows plain lyrics as text, "Instrumental", or a "Fetch from LRCLIB" button. It lives outside the rows because `AudioPreview` is mounted per row.

### Language
- `TagData.language` <-> `ItemKey::Language` (ID3 `TLAN`, Vorbis `LANGUAGE`, MP4 freeform `LANGUAGE`). It is now a curated key (`is_curated_key`, `KEPT_FIELD_KEYS` on both sides), so it no longer shows as a raw "All Tags" column and survives a strip. Covered by the existing cross-format round-trip matrix (mp3 v2.3/v2.4, flac, m4a, ogg, aiff, wav).
- `src/lib/language.ts`: ISO 639-2/T codes (matches whatlang's output and Picard), ~70 languages, `zxx` (instrumental), `mul`, `und`. Reads 639-1 (`es`, `es-MX`), 639-2/B (`fre`, `ger`) and English names. Display name column ("Spanish"), editor = existing `Combobox` of "Spanish (spa, es)" with type-ahead, free text allowed, blank clears. Column `language` is **not** added to `visibleColumns` (opt-in from the column picker).
- **Detection** (offline `whatlang` 0.18): lyrics first (stored sidecar/embedded/cache), else title + artist. Pure function `guess_language(text, source)`:
  - lyrics: >= 40 letters and confidence >= 0.4 -> a guess; **High** if whatlang says reliable, or >= 80 letters and confidence >= 0.5. Else Low.
  - title+artist: >= 10 letters and confidence >= 0.6, always **Low**.
  - cached "instrumental" -> `zxx`, High.
  - Thresholds were calibrated on real LRCLIB lyrics (see hit rate): almost every real result was confidence 1.00; the single Low (0.42) was a mixed-language chorus.
- **Never silent**: "Detect language..." (right-click) builds a preview (`PreviewMode "language"`, `buildLanguagePreview`): High suggestions for tracks with no language are ticked; Low guesses and anything that would replace an existing language are listed but unticked, with a note under the field name ("detected from the lyrics; replaces \"fra\""). A same-language value in another spelling (`es`, `fre`) is offered as a rewrite to the canonical code. `PendingChange.note` is new (rendered small under the field name).
- **`#lang-xx` in Comment** (setting `languageAppendComment`, default off): adds a Comment row next to each language row in the same preview (same tick state), replacing an earlier `#lang-..` instead of stacking. Uses the 2-letter code when there is one (`#lang-es`), else the 3-letter (`#lang-zxx`).
- **Languages facet**: `FACETS.language` (name shown via `languageName`, "No language" first), index column `language` (lowercased, indexed), `Facet::Language` arm, `INDEX_VERSION` 4 -> 5 (one full re-read on first launch, same as B1's bump). Sidebar tab "Lang." (the tab grid went 3 -> 4 columns). The sidebar rename pencil works and normalises, so renaming `es` to `Spanish` stores `spa` on every track; that is the cleanup path for libraries with mixed spellings. `matchesFacet` compares language case-insensitively because the index lowercases. Search: bare words and `lang:` / `language:` match code, 2-letter code and name.

## Hit rate (LRCLIB, 100 random tracks of the owner's 4,456-track library)
Sampled from a copy of `library-index.sqlite` (artist/title/album/duration only; no audio file was opened, nothing was written). Library is mostly dance music, which LRCLIB covers poorly.

With the 503 retry: **63 of 100 got lyrics (54 synced, 9 plain)**, 1 instrumental, 35 not found, 1 still failed after retries (LRCLIB 503). Before the retry the same sample showed 25 transient 503s (46 synced / 6 plain), so expect a busy service to cost a few percent; a re-run after the 14-day miss TTL or later the same day recovers them.
Language from those 63 lyrics: 60 High, 1 Low (0.42, a mixed-language chorus), 2 no guess (too little text). All High results looked right (English, Russian, Ukrainian, French, Spanish); watch-outs are Russian vs Ukrainian on short Cyrillic lyrics. Misses are mostly obscure dance/edit releases, which is where the title+artist fallback (always Low, unticked) applies.

## Deviations
- **AI-Clean fallback for low-confidence language is not built.** The AI backends are structured around the fixed clean-track schema (`ai_clean_batch` / `claude_clean_batch`); a language question needs its own prompt + parser. Low-confidence guesses are simply unticked in the preview. Follow-up: a `ai_detect_language` command next to `ai_clean_prompt`.
- No SYLT (see above). Sidecar plain lyrics are `.txt`.
- Fetch lyrics / Detect language are in the track right-click menu only (no toolbar buttons) to keep the shared-file edits small.
- Embedded writes do not make a `.bak`; they only touch the lyrics frame and are opt-in (default is sidecar).
- The lyrics panel does not seek on line click (needs a handle on the active `<audio>`).

## Click-through (`npm run tauri dev`; use copies of a few files first)
1. First launch re-reads the library (index v5). Library page -> column picker -> enable **Language**. Double-click a cell, type `span`, pick Spanish: shows "Spanish", the file's TLAN is `spa` (Inspect tags / Raw). Clear it with the x.
2. Sidebar -> **Lang.** tab: "No language" first, then names with counts; click loads those tracks; sort toggle; pencil on `es` -> type `Spanish` -> confirm -> every `es` track becomes `spa`.
3. Right-click a track -> **Fetch lyrics**: toast with the tally; a `.lrc` appears next to the file (Settings -> Library -> Store fetched lyrics = Sidecar). Switch to Embedded/Both and fetch with a track that has none: Raw fields show `Lyrics`. Select ~20 tracks: status bar counts up.
4. Prelisten a track that has a `.lrc`: click the **Lyrics** button (bottom right). Current line highlights and scrolls; pause keeps the panel; play another track switches it. A track with no lyrics shows "Fetch from LRCLIB".
5. Select tracks (some with lyrics) -> right-click -> **Detect language...**: Preview shows rows; lyrics-based ones ticked, title-based ones unticked with a note; Apply writes TLAN; undo from the Session changes view restores it. Turn on "Also write the language into Comment" and repeat: a `#lang-es` Comment row appears beside each.
6. Search box `lang:spa`, `spanish`.

## Sketch (not built): "Lyrics output" window for DJ + karaoke visuals
- A second Tauri window (`WebviewWindowBuilder`, label `lyrics-out`, route `/lyrics-out`), borderless, opened on a chosen monitor (the Window API exposes monitors; the DJ drags it to the projector and presses F11 / "fullscreen on monitor N"). Transparent background option for compositing in Resolume/OBS (window capture or a Spout/NDI bridge later).
- It renders the same data as `LyricsPanel`: current line big, next line small, themes (font, colour, outline, per-line fade, optional word-by-word with enhanced LRC `<mm:ss.xx>` word tags that LRCLIB sometimes has). Theme and monitor live in settings; the window only gets `{lines, timeMs, playing}` over Tauri events (`emit_to("lyrics-out", ...)`), so it has no logic of its own.
- **Following the deck** is the hard part, per source:
  - *Prelisten in this app*: already solved, `nowPlaying` is exactly the feed.
  - *Mixxx*: it has a controller scripting engine (JS) that can read `[Channel1],track_loaded`, `playposition`, `duration`, and track metadata (`engine.getValue` plus `engine.getString`), and can speak OSC/MIDI out. A tiny controller script posting `{deck, artist, title, position}` over a local UDP/WebSocket port (or writing a JSON file the app watches) gives artist/title/position at ~20 Hz. Mixxx also has the "now playing" text/OBS integration for the track name only.
  - *VirtualDJ*: has a "Now Playing"/OSC/VDJ-script output, and reads `.lrc` sidecars itself.
  - *Rekordbox*: no API. Options: (1) read the "now playing" from the OS window title / Rekordbox's History export (track names only, no position), (2) audio fingerprint of the master output (Chromaprint is already a dependency, via duplicates) to identify the track and re-sync position by matching against the local file, (3) manual: the DJ presses a hotkey or footswitch on the cue to start the lyrics clock from zero. (3) is the dependable first version; (2) is the "magic" one.
  - Position drift: with only track identity + start time, run the LRC clock locally and offer +/-100 ms nudge keys; resync on any signal that exposes position.
- Needs from this work, already in place: sidecar `.lrc` files beside the audio (any tool can read them), `lyrics_for_path`, `parseLrc`/`currentLineIndex`, `useNowPlaying`.
