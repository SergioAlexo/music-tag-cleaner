# presetforge

Synth preset conversion engine for Music Tag Cleaner. Converts presets to Vital (`.vital`) and can
render-check the results with [vita](https://pypi.org/project/vita/) (Vital's engine).

| Source | Files | Path | Fidelity |
|---|---|---|---|
| Serum 1 | `.fxp` | [serum2vital](https://github.com/btesser/serum2vital) in-process | as serum2vital |
| Serum 2 | `.SerumPreset` | serum2vital in-process | as serum2vital |
| Surge XT | `.fxp` (plugin id `cjs3`) | own reader -> UPM -> generic Vital writer | scene A only; see below |
| Dexed / DX7 | `.syx` (32-voice bank, single voice) | own reader -> UPM -> generic Vital writer | <=3 operators exact-ish FM, more is reduced |

Surge and Dexed go through the Universal Patch Model (`upm.py`, physical units plus a per-field
report) and `vital_writer.py`, which starts from Vital's own init preset
(`presetforge/data/vital_init.json`, generated by `dev/gen_vital_data.py`) and only overwrites keys the
patch sets. Curves and ranges come from vita itself (`vital_ranges.json`); FM depth was measured
(`dev/calibrate_fm.py`). Every written file is loaded back through vita in the tests.

**Surge XT**: oscillators (classic -> basic saw/square/triangle, sine, wavetable/window with the
embedded frames), filter 1/2 by family, amp and filter envelopes, LFO rate/shape (sine, triangle,
square, ramp) as modulation sources, filter EG amount, mod routings to cutoff, resonance and oscillator
pitch from velocity, keytrack, mod wheel, aftertouch, EGs and LFOs, polyphony, glide, delay, reverb 1/2,
chorus, phaser, flanger and distortion effects. Scene B (layer/split) is dropped with a note. Noise,
ring modulators, FM routing, waveshaper, filter feedback and other effects are reported as dropped.
Noise-only patches fail with an error.

**Dexed / DX7**: the 32 algorithms come from Dexed's operator flags. Operators with output level 0 are
ignored; the best <=3 operators are kept (carriers sine oscillators, modulators silent sine oscillators
that FM a carrier) and the rest are listed as dropped or approximated. Levels use Dexed's 0.75 dB table,
the modulation index is 4*pi at full level (Dexed's convention) and Vital's FM depth is looked up from
the vita measurements. Envelopes use Dexed's rate table and become attack/decay/sustain/release (always
reported as approximated). Not mapped: pitch EG (if not flat), velocity/level/rate scaling, amplitude
modulation, LFO delay and sample&hold. A baked-wavetable fallback for 4-6 operator patches is not done.

## Install

```
pip install -e presetforge             # engine + serum2vital
pip install -e "presetforge[verify]"   # adds vita + numpy for `verify`
```

Python 3.11 or newer. The console script is `presetforge`; `python -m presetforge` works too.

## Usage

```
presetforge version --json
presetforge scan <path>... --json
presetforge convert <file>... --out-dir D [--serum-root R] [--max-frames N] --json
presetforge verify <file.vital>... --json
```

- `scan` accepts files or folders (folders are searched recursively for `.fxp`,
  `.SerumPreset`, `.syx` and `.vital`). The synth is detected from file content: Serum 1 is a VST2
  `CcnK`/`FPCh` file with plugin id `XfsX`, Surge XT is the same container with id `cjs3`, Serum 2
  starts with `XferJson`, DX7 dumps start `F0 43` (a bank's `name` is the file stem, a single voice's
  is the voice name), Vital is JSON with a `settings` object. Vital is recognised but `supported:false` (it is a target, not a source).
- `convert` writes `<source stem>.vital` into `--out-dir`, adding ` (2)`, ` (3)` ... on a name clash.
  A DX7 bank produces one item per voice (`voice` 1..32 and `name` are extra optional fields, `source` is
  the bank file) and the outputs are named after the voice names; a Surge patch is named after its
  patch name.
- `verify` loads each file in Vital's engine and renders note 48 (velocity 0.8, 1 s hold,
  2.5 s total). `silent` means peak below -80 dB, `clips` means peak above 0 dB.

## Protocol

stdout carries only JSON lines (stray library prints are redirected to stderr); stderr is free text.

```
{"event":"progress","done":3,"total":10,"file":"..."}
{"event":"warning","message":"...","file":"..."}
{"event":"result","data":{...}}        exactly one per successful run
{"event":"error","message":"..."}      fatal only; the exit code is then non-zero
```

Per-file failures never abort a run: they appear inside the items (`status:"failed"`, `error`)
and the exit code stays 0. Fatal errors (bad arguments, unreadable `--serum-root`, missing
`vita` for `verify`: `verify needs: pip install presetforge[verify]`) emit an `error` line and
exit non-zero.

Item shapes:

```
ScanItem    {path, synth:"serum1"|"serum2"|"surge"|"dexed"|"vital"|"unknown", name, supported, reason?}
ConvertItem {source, output?, status:"ok"|"approx"|"failed", error?, voice?, name?,
             report:{exact, approximated:[{field,note}], dropped:[{field,note}]}}
VerifyItem  {file, loaded, peakDb?, rmsDb?, silent?, clips?, nan?}
```

Report mapping from serum2vital's notes: `unsupported:` and `conflict:` notes (and anything
saying a routing was dropped or left off) go to `dropped`; `approximation:`, `unknown:` and
other notes go to `approximated`. `field` is a best-effort label parsed from the note text
(`osc A`, `filter`, `modulation`, ... or `preset`). `status` is `approx` if either list is
non-empty. **`exact` is always 0 for Serum**: serum2vital does not expose a count of cleanly mapped
parameters (Surge and Dexed count the fields they map without approximation).

## Tests

```
pip install -e "presetforge[dev]"
pytest presetforge
```

Dexed fixtures are generated in code from the documented packed format and always run; Surge tests
build minimal `.fxp` files in code, plus read real factory patches from `PRESETFORGE_SURGE_FIXTURES`
(default: a local sparse clone of the Surge repo's `resources/data/patches_factory`) and skip when it is
missing. Tests read Serum preset fixtures from the folder named by `PRESETFORGE_FIXTURES` (default: a local
`serum2vital/DebugPresets` checkout; expects `serum1/` and `crafted/serum2/` inside) and skip
when it is missing. Fixtures are never copied into this repository.
